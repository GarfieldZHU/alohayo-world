# 世界与地形

> **Wiki 页面版本：** zh-CN 1.5.0 · **英文源版本：** EN 1.5.0 · **产品基线：** v0.1.3 · **更新日期：** 2026-08-09
> **English:** [World and Terrain](World-and-Terrain) · **同步状态：** 已同步至 EN 1.5.0

地图是核心模拟模型。地形由连续地理字段推导，而不是先绘图再补理由。同一组稳定字段同时
服务于探索、道路、聚落、生物、天气、战斗位置与自定义区域。

## 地理分层

| 层        | 示例                                  | 权威模块         |
| --------- | ------------------------------------- | ---------------- |
| 连续字段  | 海拔、湿度、温度、坡度                | 确定性生成器     |
| 水文      | 填洼高程、D8 流向、汇流量、流域、洼地 | map/Wasm 栅格    |
| 拓扑      | 海洋/湖体、大陆/岛屿身份、别名        | 拓扑解析器       |
| 地貌过程  | 侵蚀潜力、沉积物、堆积、洪泛区        | 确定性元数据     |
| 地形/材质 | 森林、沙漠、湿地、高山、冰川          | 配置驱动分类     |
| 特征      | 河流、道路、聚落、自定义覆盖          | typed feature 层 |
| 表面      | 水、泥、雪、霜、灰、烧痕              | 可逆天气/动作层  |
| 表现      | 轮廓、过渡、细节、迷雾、光照          | 引擎渲染器       |

海洋/湖泊与大陆/岛屿属于拓扑；河流是跨格子的线性水文特征；海湾、海峡、三角洲、洞穴、
半岛、悬崖和山谷属于地貌/特征层。分层避免重复 biome，并让玩法能提出精确查询。

## 地形物理契约

每个地形都必须定义现实描述、世界内行为、生成权重与条件、允许表面层、移动/操控/暴露/
进入能力/危险，以及可破坏性和变换方法。生物栖息标签、聚落适宜度、道路成本和调色板
也由配置提供。机器权威是 `terrain-rules.json` 与 `biomes.json`，中英文缺一不可。

## 表面层与变换

天气和动作先添加临时表面：雨产生积水/泥，雪覆盖道路/树冠，融雪形成泥雪，热量融冰，
火留下烧痕。只有规则明确说明底层材质变化时才改变地形 ID。移除树木或积雪不等于删除
土壤；开矿不等于把裸岩变成草地；短期洪水也不立刻创建永久三角洲。

## 流式与开发测试

区块由生成器版本、种子、坐标、大小和内容解析结果唯一决定。加载顺序、负坐标和驱逐/
重载不能改变结果。`core:terrain-showcase` 可在起点附近放置全部 26 种地形，用于 i18n、
渲染、移动、道路和天气测试；它默认关闭，不属于正常世界。

## 运输、天气与交通特征

道路生成可为满足条件的路线确定性地产生一条稀疏结构记录：桥、堤道、渡口或盘山路。
记录包含稳定 ID、中点坐标、所需能力标签、移动倍率和维护率，并参与区块/世界 hash。
角色、坐骑、载具和 AI 共用通行查询；PixiJS 标记只负责表现。

`sampleRegionalWeather` 根据种子、位置和模拟时钟返回区域身份、锋面强度、风、降水、积水、
视野、舒适度和短期预报。聚落交通聚合器复用同一天气样本与运输记录，计算有界的需求、拥堵、
维护和补给诊断。普通游戏 HUD 保持安静，这些值仅作为开发者 canvas 诊断。

## 水域地形与区块接缝

水域有三类不能混为一谈的权威：拓扑解析器决定水体是否连通海洋或为内陆湖泊；水文栅格
决定本地区域 D8 流向、汇流量与局部流域；渲染提示决定岸线如何柔化表现。

岸线字段是带符号的距离：水为负值、陆地为正值、`0` 接触水陆边界，`+/-127` 表示已知
范围内没有岸线。Worker 首次提供区块内提示；邻接区块加载后，渲染器用一格 halo 重建
接缝距离。它为深海陆架、沙滩、峭岸、湖岸、河口、三角洲、湿地与珊瑚礁提供不同材质，
但不会改变地形 ID、移动或拓扑身份。

探索迷雾由覆盖已渲染邻域的单张线性过滤 GPU 纹理合成。Typed pixel 准备复用 CPU 动作
判定的世界坐标可见性字段，在格子中心间平滑探索记忆，移动时只更新前后视野包围区域。
PixiJS 只拥有纹理，地图与玩法状态仍独立于渲染器。

动态地貌从默认关闭的地图模拟开始，只处理明确激活的排水走廊格子。第一阶段保存整数沉积物、
已堆积物、水量与 tick；每个固定步都会精确报告保留、导出、饱和损失和稀疏变化格子。出口记录
在 #38 提供全局排水身份前仅是局部临时数据，当前实况地形与存档尚不消费这些状态。

每个区块还发布 `ChunkDrainageSummary`，记录跨越四个方向边界的局部水流交接。其状态始终
是 `provisional`，尚未拥有全世界稳定流域身份。#38 负责 halo、接缝协调、河流图、持久化与
加载顺序基准；#41 已交付 halo 岸线、GPU 迷雾、专用水域材质与下游加宽河道基线。局部字段
不能被当作“河流在区块边缘结束”的证据。#44 负责把局部守恒内核推进为全局持久侵蚀、洪水、
河道演化与三角洲增长。

## 地形纹理表现

特性分支新增仅用于表现的 `terrain-texture-hints` 批次。它读取现有 biome 与气候数组，返回
一个紧凑的 `pattern` 字节层；高半字节是材质配方，低半字节是密度预算。Rust/Wasm 只准备语义
材质配方；TypeScript/PixiJS 复用已有 render-hint 噪声，并在既有 regional-details 批次中负责
纹理图案、调色、透明度、LOD 与显示对象生命周期。

该覆盖层增加水面波纹、海岸砂纹、草屑、林冠点、湿地芦苇、岩石切面、雪粒与火山灰痕迹，但不改变
地形 ID、拓扑、水文、移动、存档或既有地形颜色。纹理变化使用世界坐标，因此区块重载和负坐标不会
重置视觉相位。
